# Logbook — P7 citation-parsing test failure root-caused: the prompt's own example was the bug

**2026-09-15.** Surfaced by the full `pytest -q` run right after the weighted-fusion fix
(`LOGBOOK_09152026_071646.md`) — two new failures in `tests/answer/test_answer_pipeline.py`,
unrelated to that fix (confirmed: this test doesn't touch `HybridIndex`'s fusion mode at all).

## Symptom

```
AssertionError: assert 'chunk_id bm25::0' in ['bm25::0', 'unrelated::0']
```
The model's answer contained a citation like `[chunk_id bm25::0]` instead of `[bm25::0]` — the
citation regex (`\[([^\[\]]+)\]`, correctly permissive by design) extracted it verbatim, and it
correctly failed validation against the real retrieved chunk ids.

## Root cause

`src/answer/prompt.py`'s `SYSTEM_INSTRUCTIONS` told the model to cite claims "in square brackets,
**like this: [chunk_id]**" — using the literal placeholder word `chunk_id` as the illustrative
example. That string is syntactically indistinguishable from a real citation to a small model: the
3B local model (Qwen2.5-3B, CPU inference, already documented as needing `repeat_penalty` tuning for
degenerate repetition — `60d2187`) sometimes echoed the literal instructional word back, or blended
it with a real id, instead of substituting a real value. The actual passages in context already show
real ids correctly (`build_prompt`'s passage block is `[{chunk_id}] (from {doc_id}): ...`) — the bug
was purely in the instructional example text, not in how real ids were presented.

## Fix

Rewrote the instruction to give a concrete example using a plausible-looking id (`[abc123::0]`) and
explicitly told the model NOT to write the literal word `chunk_id`:
```
"...copy the exact bracketed id shown right before the passage, verbatim. For example, if a
passage below starts with [abc123::0], write [abc123::0]. Do not write the literal word
\"chunk_id\" -- always substitute the real id shown, never the placeholder name."
```
Kept the phrases `tests/answer/test_prompt.py` asserts on ("chunk id", "square brackets", "say so")
intact so those 5 fast unit tests didn't need changing — verified locally before shipping.
