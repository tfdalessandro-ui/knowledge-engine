## The actual P2 result at 100+ queries: still fails, same sign

```
=== BM25-only, 106 queries ===
nDCG@10: 0.9017   MRR: 0.9370   recall@20: 0.9308

=== Hybrid, 106 queries ===
nDCG@10: 0.8872   MRR: 0.9051   recall@20: 0.9686

Relative improvement: (0.8872 - 0.9017) / 0.9017 = -1.61%
```

**Growing the judgment set 3.5x (30->106 queries) did not flip the sign or
meaningfully change the magnitude** -- still hybrid scoring below
BM25-only, still around -1.6 to -1.7%, essentially the same result as the
30-query set's -1.68%. This is itself an important, disclosed finding:
**the earlier hypothesis that a too-small judgment set was distorting the
measurement is now much less credible.** With more than 3x the queries
and pairs, and still landing in almost exactly the same place, the
regression looks like a real property of this corpus/RRF-fusion
combination at its current small scale (47 docs), not a measurement
artifact of an undersized judgment set. Confirming with the actual
`pytest` exit-criterion test (fresh-built indices) is running in the
background as of this entry -- **not yet complete, do not assume its
number matches the live-index estimate above without checking**, though
the live-index number matched closely (within ~0.1%) on every prior
occasion this was cross-checked.

## Updated understanding of the P2 gap, after four attempts

1. Accept-as-is -- fallback.
2. Grow judgment set 28->30 queries -- made it worse, flipped sign
   negative (`LOGBOOK_09032026_155830.md`).
3. GA-tune RRF/fanout parameters -- confirmed overfitting via
   cross-validation, not deployed (`LOGBOOK_09032026_161900.md`).
4. Grow judgment set further, 30->106 queries -- **this entry**: still
   negative, essentially unchanged from attempt 2's magnitude.

The consistency between attempts 2 and 4 (both land near -1.6 to -1.7%
despite a >3x difference in judgment-set size) is the most informative
result of this whole investigation so far: it suggests the regression is
not primarily a judgment-set-size artifact at all. The more likely
remaining explanation, not yet tested: RRF's blending genuinely
underperforms BM25-alone on THIS corpus's specific query mix (many
short, literal, well-matched keyword queries against a small,
topically-concentrated document set) at the DEFAULT rrf_k=60 -- which the
GA investigation (attempt 3) also brushed up against before being
disqualified for overfitting on too few held-out queries per fold. With
106 queries now available, a properly cross-validated parameter search
(same GA-with-CV methodology as attempt 3, but with ~20+ queries per
held-out fold instead of ~6) would be a much more trustworthy test than
attempt 3's -- untested, a natural next step if this is pursued further,
but not undertaken in this entry to avoid repeating the same overfitting
mistake at a scale that still might not be large enough.
