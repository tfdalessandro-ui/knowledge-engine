## Finding

`ke-research-crawl` and `ke-research-loop` failed with `ModuleNotFoundError: No module named 'research'`.
**This did not come from the rename.** The logs show the same error under the old
`/home/sensalis/work/knowledge_engine/` path on 15 and 16 Sep 04:00 UTC, both before the rename.
The last successful runs were on 14 Sep.

Root cause: the same gap that lost `weighted_fusion.py` and `p7_batch_run.py`. These files existed
only on the node and were never committed to git, so the 14 Sep switch to a git clone dropped them
without any error. A full diff of the backup against the current tree found 13 lost files, not just the one package:

- `src/research/` (4 files): breaks `ke-research-crawl` and `ke-research-loop`
- `src/discovery/` (6 files): Step 8 on-demand discovery; `scripts/benchmark_cx23_discovery.py` imports it
- `src/eval/adaptive_alpha.py`: `scripts/auto_tune.py` imports it, so the recurring auto-tune (crontab entry `KE_AUTO_TUNE`) was also broken
- `tests/discovery/test_discovery.py`, `tests/eval/test_adaptive_alpha.py`

## Fix

Restored the files unchanged from `~/work/knowledge_engine_pretar_backup_20260914`, committed them (`cfb2175`), and
synced the node's clone to that commit. On the node, the committed files match the restored copies exactly.
