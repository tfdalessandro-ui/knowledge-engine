# Logbook — Backup dir decision: keep it; it holds production features the 14 Sep migration silently lost

**2026-09-17 (04:15 UTC).** Subject: `~/work/knowledge_engine_pretar_backup_20260914` on sensalis-node (4.6 GB, not a git
repo), the snapshot taken just before the 14 Sep tar-ship → git-clone migration.

## Method

Every file except `.venv` (2.3 GB, reproducible) and caches (777 files) was classified by content:

| Class | Files |
|---|---|
| byte-identical at the same path in `~/work/ose` | 730 |
| content present in OSE git history (any commit, any path) | 12 |
| **content found nowhere else** | 35 |

(A first pass misclassified 47 files as unique because `git -C ose hash-object` resolved the backup's relative paths from the wrong
directory. Re-run with absolute paths → 12 of the 47 were in git history.)

The 35 unique files, examined one by one:
- **8 redundant after all**: `query_log.db` and `merge_review.db` (every backup row is present in the current databases:
  272/272 queries, 3,849/3,849 candidates, 3/3 merge candidates), `auto_tune_state.json` (superseded by a newer run), and corpus documents
  `doc26`–`doc30` (differ only in line endings).
- **27 meaningful**: see `recovery/pretar_20260914/RECOVERY.md`.

## Finding: lost production features (worse than the 16 Sep file restore suggested)

The migration also dropped node-only **edits inside files that were already tracked**, not only whole node-only files. Still missing from
live code:

1. **Crawl TTL re-fetch + content-hash change detection** (`src/crawl/pipeline.py`, 3 tests). Since 14 Sep the live
   crawler has treated every fetched URL as permanently unchanged (`ose-crawl` logs `unchanged=12` daily), so the
   "continuous crawler" that MASTER.md describes as having "real re-fetch/TTL" has not re-fetched anything.
2. **7 crawl allowlist entries** (live list: 12 URLs).
3. **`/search` → on-demand discovery trigger for sparse results.** The `discovery/` package came back on 16 Sep but isn't wired in,
   so `discovery_enabled` does nothing (this is why `/discover`-style behavior was absent in the 16 Sep check).
4. **Adaptive alpha** in `HybridIndex`/`eval.run`/API (TODO item 10 had it as "unimplemented"; it was implemented, then lost).

## Decision

- **Keep the backup folder.** It was the only on-disk copy of the above: neither node backup covers it
  (`node_backup_full.sh` pulls CX23's `/root`; the offsite restic include list only covers `~/work/catalog` and the PDF
  archive). **Not renamed**: many logbooks cite this exact path.
- **Made durable offsite:** the 27 meaningful files are committed under `recovery/pretar_20260914/` (sha256-verified identical to
  the node backup; `.gitattributes` `-text` keeps them byte-exact; a `.gitignore` exception for its `log/`).
- **Made read-only** on the node (`chmod -R a-w`; reversible with `chmod -R u+w`).
- **Not deleted, including the 2.3 GB `.venv`.** The node has 61 GB free (73% used), so reclaiming space isn't worth an irreversible
  step. Once TODO item 13 is done, the folder is fully redundant and can be removed with the owner's confirmation.
- Restoring the 4 features is **TODO item 13**: port them onto current code one at a time with regression tests, not by
  copying the old files over (the code has changed since: instance settings, `OSE_` prefix, weighted-fusion rewiring).
