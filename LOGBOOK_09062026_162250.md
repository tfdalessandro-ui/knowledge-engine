## A real miscalibration, caught live, not glossed over

First `is_sparse()` implementation: "no hit in the top N has a non-null
bm25_score." Tested against a genuinely off-topic query (`zebra migration
patterns east africa`, chosen specifically for zero real vocabulary
overlap with this search-infra corpus) -- **it did NOT trigger.** The
top hit had `bm25_score=4.29`, a real nonzero score, from a single
incidental token overlap with an FTS5 documentation page. "Not None" was
too weak a bar.

Second attempt: added `MIN_MEANINGFUL_BM25_SCORE = 3.0` as a threshold --
**caught before deploying it**: 4.29 is already above 3.0, so this
wouldn't have fixed anything either; a genuine reasoning slip caught by
re-checking the actual number rather than assuming the fix worked.

Third attempt, the one actually deployed: `MIN_MEANINGFUL_BM25_SCORE =
5.0`, chosen from two real data points -- the confirmed false positive
(4.29) and this session's own confirmed real matches (5.6-15+, from
`query_log.db` and live queries earlier today). Re-tested against the
same query: **`discovery_triggered: true`.** Disclosed explicitly in the
code's own comment that this is a two-point calibration, not a
statistically robust one, and worth revisiting with more real data if it
misfires again -- not presented as more solved than it is.

output: the hard-cap log line originally computed "candidates left
