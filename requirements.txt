# Pinned via `pip freeze` inside a clean venv (see HELP.md for the exact recreation steps).
# Direct dependencies are marked; everything else is a transitive pin kept for
# byte-for-byte reproducibility between the dev laptop and CCX23.
#
# NOTE (P1): docling pulls in torch/torchvision/transformers -- this is a large,
# ML-heavy install (~1.8GB), not incidental bloat. It's the P1 roadmap's chosen
# parsing library. First real PDF parse also downloads OCR/layout model weights
# from HuggingFace/ModelScope at runtime (not at pip-install time) -- see
# HELP.md "Network dependency" note before assuming this repo is fully offline.
#
# NOTE (P2): sentence-transformers similarly downloads the BGE-Small embedding
# model (~130MB) from HuggingFace on first use, cached afterward. This one is
# NOT optional/gated like PDF -- embeddings are P2's actual deliverable -- so
# the first `ingest.pipeline` run (and the P2 tests) need network access once.
#
# CRITICAL (P1, learned the hard way on sensalis-node): installing `torch` from
# plain PyPI on Linux pulls the CUDA build by default, which drags in ~1GB+ of
# nvidia-* packages (cudnn, nccl, cusparselt, cublas...) even on a CPU-only,
# no-GPU machine -- directly contradicting this project's CPU-first premise.
# ALWAYS install torch/torchvision from the CPU wheel index FIRST, then the
# rest of this file (pip will see torch/torchvision already satisfied and
# leave them alone):
#   pip install torch==2.14.0 torchvision==0.29.0 --index-url https://download.pytorch.org/whl/cpu
#   pip install -r requirements.txt
# (On Windows this isn't an issue -- PyPI's default Windows torch wheel has no
# CUDA extras -- but do it the same way everywhere for consistency.)
